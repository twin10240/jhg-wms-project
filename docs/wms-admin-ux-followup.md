## 포트폴리오 1차 검증 대기

- 375px와 1280px에서 핵심 작업이 가려지지 않는지 확인
  — 2026-07-26 확인분은 V1 화면 기준. V2 이후 추가된 `returns`·`returndetail`·`cycle-counts`·
  `cycle-count-new`·`cycle-count-detail` 5개는 **미확인**. 입력 요소가 든 표(실사 상세 9열,
  반품 상세 검수 폼)가 좁은 화면에서 손이 닿는지가 관건이다. 반려 모달도 함께 볼 것.
- 실제 데이터로 대시보드 집계와 목록 건수 대조
- OPERATOR 버튼 미노출과 직접 POST `403` 확인
- 로그인 성공·실패·로그아웃, API 미인증 `401` 확인

## 1차 이후 후보

### 재고 조정 안전성

- 상품 선택 시 현재 보유·예약·가용수량 동시 표시
- delta 입력 중 조정 후 예상 보유수량 표시
- 음수 조정 사유 필수와 별도 확인
- 완료 flash에서 변경 전후 수량과 원장 링크 제공

**권한: OPERATOR도 조정할 수 있다(의도).** 파손·오차를 현장에서 즉시 보정해야 하므로
MANAGER 전용으로 두지 않는다. 실사의 제출자·승인자 분리를 우회하는 경로이지만 운영상 필요로 감수한 결정이며,
통제는 사전 승인이 아니라 사후 추적 — 모든 조정이 ADJUST 원장에 actor와 함께 남는다.
권한을 조이려면 이 결정부터 뒤집어야 한다(`SecurityConfig` 주석, `WmsAdminControllerTest.OPERATOR도_재고를_조정할_수_있다`).

**실사 중인 상품은 조정이 거부된다**(2026-08-26). 승인이 계수값을 절대값으로 덮어써서
조정 효과가 사라지는 혼선을 막는다. 출고·입고·반품은 막지 않는다.

현재 서버는 0 미만과 예약수량 미만 감소를 방어하고 모든 성공 조정을 원장에 기록한다.
예측 UI는 수동 검증에서 오입력 위험이 확인될 때 추가한다.

### 목록 탐색

- 재고 기본 정렬을 가용수량 오름차순으로 변경
- 대시보드 숫자를 정확한 상태 필터 목록으로 연결
- 원장 상품·기간 검색 또는 페이지네이션

현재 데이터는 20 SKU이고 원장은 최신 200건으로 제한돼 있어 1차 범위에서는 보류한다.

### 모바일 밀도

- 넓은 표를 카드형 행 또는 핵심 열 우선 표시로 전환
- 버튼·입력의 터치 영역 추가 조정

현재는 표 컨테이너 내부 스크롤을 사용한다. 수동 검증에서 핵심 작업이 어려울 때만 확장한다.
