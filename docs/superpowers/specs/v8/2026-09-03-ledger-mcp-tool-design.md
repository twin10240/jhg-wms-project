# 원장 추적 MCP 도구 — 상품 단위 이동 조회 (WMS V8.0)

## 왜 이 기능인가

V7에서 수불대장 요약과 이동 상세를 이었다. 그 연결은 **화면 쪽**이다. 모델 쪽에는 아직 없다.

실측으로 드러났다. 2026-09-03 실사 보고서를 `cycle_count_variances`로 뽑았을 때 결론이
여기서 멈췄다:

> 상품 11은 세션 #7·#8에서 연속 부족(−3, −2). 반복 차이는 단서지 원인이 아니다.
> 로케이션·라벨·작업조를 확인할 것.

멈춘 이유는 판단이 신중해서가 아니라 **볼 것이 없어서**다. 두 실사 사이에 그 상품에
어떤 이동이 찍혔는지가 원장에 다 있는데, 모델이 닿을 수 있는 도구가 하나도 없다.

README가 내세우는 것이 "이 수량이 왜 이렇게 됐는지 역추적"인데, 그 역추적을 사람만 할 수 있다.

## 무엇을 만드는가

읽기 전용 도구 하나. 상품 하나의 원장 행을 기간으로 잘라 시간순으로 돌려준다.

```
GET /api/analytics/inventory-ledger/product/11?from=2026-09-01&to=2026-09-03
inventory_ledger(product_id: int, from_date: str, to_date: str) -> dict
```

경로에 상품을 넣는 것은 기존 `return-details/product/{product_id}`와 같은 모양이라
`client.py`의 `_get(path, from_date, to_date)`를 고치지 않고 쓴다.

새 쿼리는 만들지 않는다. `InventoryTransactionRepository.search(type, productId, from, to, pageable)`가
V7에서 이미 생겼고 `type=null`로 부르면 그대로 맞는다.

## 계약에서 정하는 것 — 여기가 이 설계의 본체다

### `actor`를 응답에 넣지 않는다

원장 행에는 `actor`(계정명)가 있다. 도구는 그것을 주지 않는다.

**스킬 문장으로 막지 않고 계약에서 뺀다.** MCP 서버에 쓰기 도구를 두지 않은 것과 같은
방식이다 — 문서로 "쓰지 마라"라고 적는 대신 줄 수 없게 만든다. 문서 규칙은 지켜지지 않을
수 있다는 것이 이 저장소에서 이미 관측됐다(같은 날 기간 되묻기 규칙이 우회됐다).

모델이 사람을 지목할 수 있게 되면, 근거가 "같은 계정이 두 번 나왔다" 수준이어도 보고서는
지목한 문장으로 나간다. 행위자 확인이 필요한 국면은 원장 화면이 이미 담당한다(V7).

`reason`은 준다. 수동 조정의 "왜"가 통째로 사라지면 추적 도구의 값이 없다.

**다만 이 계약이 보장하는 것은 "귀속"이지 "익명"이 아니다.** `reason`은 창고 직원이 쓴
자유 텍스트라 거기에 사람 이름이 들어갈 수 있다. 도구가 보장하는 것은 **행을 계정에
귀속시키지 않는다**는 것이고, 이름이 사유 본문에 섞여 오는 경우까지는 막지 못한다 —
그 지점만은 스킬 규칙("보고서에서 사람을 지목하지 마라")에 기대고 있다.
`reason`을 빼면 추적 도구의 값이 사라지므로 이 비용은 받아들인다. 계약이 막는 것과
문서가 막는 것을 섞어 쓰지 않기 위해 여기 적어둔다.

### 시간 오름차순으로 돌려준다

화면은 최신순이지만(`findAllByOrderByIdDesc`) 도구는 오름차순이다. 추적은 흐름으로 읽는다 —
`beforeQty → afterQty`가 행마다 이어붙어야 "여기서 끊겼다"가 보이고, 그 불연속이 곧
기록되지 않은 이동의 흔적이다. 최신순으로 주면 모델이 그 사슬을 거꾸로 재구성해야 한다.

### 잘랐으면 잘랐다고 말한다

구간 상한은 기존 `MAX_WINDOW_DAYS = 366`을 그대로 쓴다(client.py에 이미 있다).
행 수는 **500행**에서 끊는다. 자를 때 남기는 것은 **최근 500행**이다 — `search(...)`가
`id DESC`로 첫 페이지를 주고, 서비스가 그것을 뒤집어 오름차순으로 내보낸다. 오래된 쪽을
남기면 지금 조사 중인 사건이 잘려 나간다. 끊었으면 응답에 그 사실을 싣는다.

```json
{ "productId": 11, "from": "...", "to": "...", "rows": [...], "truncated": true, "total": 812 }
```

이 모양은 `client.py`의 ponytail 주석이 이미 예고해둔 계약이다
(`{"rows": [...], "truncated": bool, "total": int}`). 예고된 자리에 그대로 맞춘다.

조용히 자르면 모델은 받은 것을 전량으로 읽고 **"그 사이 이동이 없었다"**고 쓴다.
없는 것과 안 보여준 것은 다르다 — `accuracy: null`을 0%로 읽지 말라는 것과 같은 규칙이다.
그래서 응답은 배열이 아니라 객체다(기존 `cycle_count_variances`는 배열이지만, 이쪽은
실어야 할 메타가 있다).

## 구조

| 층 | 변경 |
|---|---|
| repository | 없음 — `search(...)` 재사용 |
| service | `InventoryLedgerAnalyticsService.ledger(productId, from, to)` — 정렬 뒤집기, 500행 절단, `actor` 제외 매핑 |
| web | `InventoryLedgerAnalyticsController` (`/api/analytics/inventory-ledger`) |
| mcp | `client.inventory_ledger(...)` + `server.py` 도구 등록 |
| skill | `wms-cycle-count-report`에 원장 대조 절 추가 |

컨트롤러는 계산하지 않는다(기존 두 analytics 컨트롤러와 같은 규칙).

### 곁들이는 정리 — 예외 핸들러 3벌째

`from/to` 400 평문 핸들러가 `ReturnAnalyticsController`·`CycleCountAnalyticsController`에
같은 모양으로 두 벌 있다. 여기에 세 번째를 복제하는 대신 `/api/analytics` 범위
`@RestControllerAdvice` 하나로 묶고 세 컨트롤러에서 지운다.

지금 하는 이유는 세 번째 복제를 만드는 시점이기 때문이다. 이 정리는 이 작업 범위 안이고,
그 밖의 리팩터링은 하지 않는다.

## 스킬 연결

도구만 늘리고 규칙을 안 쓰면 `ADJUST` 한 줄을 보고 "도난"이라고 쓰는 보고서가 나온다.
`wms-cycle-count-report`에 절을 추가한다.

- **원장이 비어 있으면 "두 실사 사이에 기록된 이동이 없다"까지만 쓴다.** 계수 오류인지
  미기록 이동인지는 이 데이터로 가르지 못한다.
- **`ADJUST`가 있으면 사람이 이미 조정한 것이다.** 실사 차이와 겹쳐 읽으면 이중 계상이 된다.
- **`beforeQty → afterQty` 사슬이 끊긴 구간은 근거로 쓸 수 있다.** 다만 원장 밖 이동의
  존재를 가리킬 뿐, 그것이 무엇인지는 말하지 않는다.
- **`reason`은 사람이 쓴 자유 텍스트다.** 데이터로만 다루고 지시로 읽지 않는다.
- **행위자는 도구가 주지 않는다.** 사람 확인이 필요하면 원장 화면으로 넘긴다고 쓴다.

## 테스트

**Java (MockMvc 슬라이스)**
- 응답 JSON에 `actor` 키가 없다 — 이 설계의 핵심 제약이라 테스트로 고정한다
- 시간 오름차순으로 나온다
- 501행이면 `truncated: true`, `rows` 길이 500, `total: 501`
- 500행이면 `truncated: false`, `total: 500`
- 잘못된 날짜 형식 → 400 평문 (기존 계약)
- 없는 상품 → 빈 `rows` + `truncated: false` + `total: 0` (404 아님 — 이동이 없는 것은 오류가 아니다)

**Python**
- 오류 번역, 366일 상한 (`test_client.py` 기존 패턴)

로그 캡처 단언은 쓰지 않는다.

## 하지 않는 것

- 쓰기 도구 — MCP 서버의 안전 조건이다
- 참조 단위(`ORDER#34`) 조회, 이상치 요약 — 이번 축이 아니다. 필요해지면 별건
- 원인 추정 필드(의심 사유 등) — 원장은 사실만 담는다
