- 로컬: `../jhg-commerce-project/docs/manual-verification-scenarios.md`

WMS 변경을 검증할 때도 기준본의 로그인·API 401·부분입고·발주 취소·원장·권한·대시보드
시나리오를 사용한다. 결과와 캡처는 기준본의 검증 기록 표에 한 번만 기록한다.

## WMS 단독 실행 기록

시나리오 정의와 상세 결과는 기준본에 두고, 여기에는 **WMS 저장소에서 언제·무엇을 돌렸는지**만 남긴다.

### 2026-07-26 — WMS 단독 시나리오 32/32 통과

- **범위**: 로그인·로그아웃 / API 401 / 보충요청 승인·반려 / 부분입고·전량입고 / 부분입고 발주 취소 / 재고 조정·원장 / 이력 화면·필터 / 권한 / 대시보드 집계
- **방법**: Playwright 헤드리스로 실제 화면을 조작하고 상태를 단언, API 인증은 `curl`. 자동화 스크립트는 일회성이라 저장소에 두지 않는다.
- **환경**: `local` 프로파일로 스키마를 리셋해 클린 상태에서 시작. **OMS는 중단** — 보상 스윕(60초 주기)이 WMS에 예약을 걸어 대시보드 집계 대조를 오염시키기 때문.
- **결과**: 단언 32건 전부 통과. 주요 확인 —
  - 취소: 발주 `CANCELLED` + 연결 요청 `CANCELLED` + **입고분 보존** + **신규 원장 행 없음** + 입고 수단 미노출
  - 부분입고 중 요청은 `APPROVED` 유지, 전량입고 시점에만 `FULFILLED`
  - `/api/**` 미인증 401이며 `Location` 헤더 없음(폼 로그인 리다이렉트로 새지 않음)
  - OPERATOR가 MANAGER 액션을 직접 POST하면 403
- **후속 조치**: 취소·완료 발주 상세에 "이번 입고" 입력칸이 남던 것을 진행 중 상태에서만 렌더하도록 수정.

**미수행(범위 밖)** — OMS 연동(주문·취소·백오더·FIFO·출고), 장애와 복구, 최종 화면·반응형.
이들은 두 앱을 함께 띄워야 하므로 기준본 절차로 수행하고 결과도 기준본에 기록한다.
